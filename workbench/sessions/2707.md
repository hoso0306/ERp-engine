## 1. Chuyển domain production sang `erp.thanglongstar.com`

Khách mua domain `thanglongstar.com`, trỏ nameserver sang Cloudflare, quyết định dùng subdomain `erp.thanglongstar.com` (không dùng domain gốc), **thay hẳn** domain cũ `kynangai.cloud` (không chạy song song).

**Đã làm trên VPS (`14.225.211.11`, `/opt/erp`):**

1. Cloudflare: DNS `A` record `erp.thanglongstar.com` → `14.225.211.11` (Proxied), SSL/TLS mode Full (strict), tạo Origin Certificate wildcard (`*.thanglongstar.com` + `thanglongstar.com`).
2. Backup cert cũ (`kynangai.cloud`) vào `docker/nginx/certs/backup-kynangai/` và `.env.production.bak-kynangai` trước khi ghi đè.
3. Ghi Origin Certificate + Private Key mới vào `docker/nginx/certs/origin.pem`/`origin.key`, verify bằng `openssl x509`/`openssl rsa -check`.
4. Reload nginx (`docker compose exec nginx nginx -s reload`) để áp dụng cert mới — nginx dùng `server_name _` dùng chung 1 cert cho mọi domain, không cần sửa file nginx.
5. Sửa `.env.production`: `NEXT_PUBLIC_API_URL=https://erp.thanglongstar.com` (biến build-time, đổi domain bắt buộc phải rebuild lại image `web`).
6. Rebuild + restart container `web` (`docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build web`).

**Hệ quả cần biết:** vì nginx dùng chung 1 cert, domain cũ `kynangai.cloud` **đã ngừng hoạt động** (lỗi SSL 526 phía Cloudflare) — đúng theo quyết định "thay hẳn". Nếu có link cũ cần giữ, phải tạo Redirect Rule ở Cloudflare (zone `kynangai.cloud`) sang `erp.thanglongstar.com` — **chưa làm**, khách chưa yêu cầu.

**Đã verify:** `curl https://erp.thanglongstar.com/api/health` → `database: ok`; `/` → redirect đúng `/login`; `/login` → HTTP 200. Chưa xem qua trình duyệt thật (đăng nhập + luồng chính) — khách tự kiểm tra.

**Lưu ý bảo mật:** Private Key gốc (đã dùng cho cert này) từng được dán vào chat dưới dạng ảnh chụp màn hình + text trước khi ghi lên VPS — đã cân nhắc rủi ro cùng khách (rủi ro thấp vì chỉ là TLS origin cert giữa Cloudflare–VPS, không phải quyền admin hệ thống), khách chọn giữ nguyên dùng thay vì revoke tạo lại.

## 3. Mặc định một số trường khi tạo khách hàng mới (form UI + Excel import)

Yêu cầu: khi tạo khách hàng mới (form hoặc import Excel), nếu không chọn/không điền thì tự động mặc định:

1. Nhóm khách hàng → luôn "Đại lý".
2. Mức độ ưu tiên → Trung bình (MEDIUM).
3. Thời hạn công nợ → 30 ngày.
4. Hạn mức công nợ → 30.000.000đ.

**Rà soát trước khi code:** mục 2 (MEDIUM) và mục 3 (30 ngày) **đã có sẵn** mặc định đúng như yêu cầu ở cả form UI lẫn backend (`create()`/`importExcel()`) — không cần sửa. Chỉ 2 mục 1 và 4 là cần thêm mới.

**Quyết định phạm vi (hỏi trực tiếp khách trước khi code):** mặc định "Đại lý" chỉ áp dụng lúc **tạo khách hàng mới**; khi import Excel gặp khách đã tồn tại (trùng SĐT, chỉ merge field trống), **không** tự gán "Đại lý" cho khách cũ đang thiếu nhóm — tránh sửa nhầm dữ liệu khách đã có sẵn ngoài ý muốn.

**File thay đổi:**

- Backend `apps/api/src/customer/customer.service.ts`:
  - Thêm hằng `DEFAULT_CUSTOMER_GROUP_NAME = 'Đại lý'`, `DEFAULT_DEBT_LIMIT = 30_000_000`.
  - Helper mới `getDefaultCustomerGroupId()` — tra `CustomerGroup` theo tên "Đại lý" (`findUnique` vì `name` là unique), trả `null` nếu không tồn tại (không throw lỗi — ví dụ nếu sau này ai đó xoá/đổi tên nhóm, dù hiện tại **chưa có** API xoá/sửa `CustomerGroup` nào trong hệ thống, chỉ có `GET /customers/groups`).
  - `create()`: `customerGroupId` mặc định qua helper trên khi không truyền; `debtLimit` mặc định `DEFAULT_DEBT_LIMIT` khi không truyền (thay vì 0 như cũ).
  - `importExcel()` (nhánh `toCreate`, dòng tạo mới): áp dụng đúng 2 mặc định trên; nhánh `toUpdate` (khách đã tồn tại) không đổi, giữ nguyên logic merge field trống cũ.
- Backend test `apps/api/src/customer/customer.service.spec.ts` — thêm `describe('create() — mặc định nhóm KH + hạn mức công nợ')` (3 test: tự gán mặc định khi không truyền; không ghi đè khi khách đã chọn; nhóm "Đại lý" không tồn tại → về `null` không lỗi).
- Frontend `apps/web/src/components/customer/customer-form.tsx`:
  - Dropdown "Nhóm khách hàng" chuyển từ uncontrolled (`defaultValue="none"`) sang controlled (`value`/`onValueChange`) — cần thiết vì phải tự chọn "Đại lý" **sau khi** danh sách nhóm tải xong từ API (`GET /customers/groups`), không thể set tĩnh lúc mount.
  - Input "Hạn mức công nợ": `defaultValue` đổi từ `0` → `30000000`.
  - Ưu tiên/Thời hạn công nợ: giữ nguyên (đã đúng).

# 3. Rebuild + restart cả api lẫn web (đổi cả backend service lẫn form FE)
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build api web

# 4. Verify
curl -s https://erp.thanglongstar.com/api/health
# Đăng nhập thật, vào /customers/new, xác nhận:
